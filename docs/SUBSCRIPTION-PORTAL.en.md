## Individual protocol links

The **unbranded** public subscriber page lists all enabled Soar, CottenDNS and MasterDNS protocol profiles for each delegated tunnel zone. Each profile has its **own actual connection URL**, **Copy config**, **Open**, and independently expandable **Show QR** with a larger QR modal. Every QR is encoded on the server from the exact protocol configuration, not from the subscription URL. The separate **Copy subscription** button only copies the subscription URL. No DNSFabric or WhiteDNS product branding is displayed to customers.

## Routes

| Path | Purpose | Compatibility |
|:--|:--|:--|
| <code>/sub/TOKEN</code> | Original WhiteDNS subscription endpoint | **Unchanged** |
| <code>/s/TOKEN</code> | Shorter, shareable app subscription link | Same content and usage headers as original |
| <code>/u/TOKEN</code> | Branded browser-facing dashboard: status, used traffic, remaining quota, total quota, expiry and QR | Uses the existing bearer token |

Example: <code>https://panel.example.com/s/TOKEN</code>. The <code>example.com</code> hostname is reserved for documentation only. The token is generated by WhiteDNS and **must not be published**.

Browser navigations to <code>/s/TOKEN</code> now show the subscriber dashboard automatically. WhiteDNS Android and other clients requesting a raw subscription continue to receive the original body and headers. A forced <code>?format=base64</code> or <code>?format=plain</code> always returns raw data. Legacy <code>/sub/TOKEN</code> remains a raw-only URL.

The new routes preserve the original 256-bit random subscription token, existing tunnel keys, user database and traffic counters. The original <code>/sub/</code> endpoint and its plain/Base64 formats remain available.

## Compatibility

This integration is pinned to official **WhiteDNS Server Management 0.8.2**. It is not an upstream WhiteDNS release. Supported system architectures are Linux amd64 and arm64 with the standard <code>soar-panel.service</code> installation layout.

### Safe preflight — no changes

~~~bash
curl -fL --show-error --retry 3 \
  -o /root/dnsfabric-update-subportal.sh \
  https://raw.githubusercontent.com/Net-spoof/dnsfabric/main/update-subportal.sh

bash -n /root/dnsfabric-update-subportal.sh
bash /root/dnsfabric-update-subportal.sh --check
~~~

### Install on an already running WhiteDNS v0.8.2 VPS

~~~bash
bash /root/dnsfabric-update-subportal.sh
~~~

The guarded updater verifies the installed version and systemd binary path, downloads the corresponding GitHub Release asset, checks its SHA-256 checksum, saves a root-only binary/access configuration backup, stops the panel briefly, backs up its database, swaps **only the server binary**, restarts the service and rolls the binary back if startup fails.

The resulting backup path is printed, under <code>/root/dnsfabric-subportal-backup-*</code>.

## Using the panel

1. Open **Accounts** and select **Link / QR** for the account.
2. Select **Subscription** to view the short <code>/s/TOKEN</code> URL and QR.
3. Use **Subscription portal** to open the <code>/u/TOKEN</code> account dashboard in a separate tab.
4. To revoke a shared link, use the existing **Rotate subscription** action. This invalidates both the old short URL and its portal page without changing tunnel keys.

## Add to App button

The primary subscription action is now **📱 افزودن به برنامه (Add to App)**. Tapping it copies the HTTPS subscription URL and opens a short guide showing where to paste it inside the compatible Android app: **Profiles → Connection → Import**. If automatic clipboard access fails, the page explains how to copy the link manually.

**Compatibility note:** The current official Android app declares ACTION_VIEW deep links only for individual profile schemes (`soar://`, `cottendns://`, `masterdns://`, `stormdns://`), **not** for automatic import of HTTPS subscription URLs. This control does not falsely claim that the app has automatically imported the subscription. Individual **Open** profile controls continue to use the recognized protocol deep links.

## Protocol QR controls

Open a browser-facing `/s/TOKEN` link, expand **Show QR** on any enabled protocol card, then use **Enlarge** for a larger image. The protocol URL is embedded in that QR; the subscription QR is shown separately under **Subscription tools**. All QR images are served by the same VPS and require the existing bearer token; no third-party QR API is used.

## Security and operational boundaries

- A subscription URL is a **bearer secret**: anyone possessing it can access active profiles and the corresponding usage dashboard.
- The browser portal is intentionally outside the administrator's private login path. It must never disclose admin credentials or internal database details.
- The portal is set to <code>Cache-Control: no-store</code>, no-referrer, and no-index.
- DNSFabric does not create new client accounts, change quotas or reset counters as part of this update.
- An upstream panel update can replace this custom binary. Verify compatibility before upgrading WhiteDNS again.
- The GitHub Actions workflow compiles patched upstream source at an exact commit and runs unit tests. Real VPS rollout must still be validated on the target server.
